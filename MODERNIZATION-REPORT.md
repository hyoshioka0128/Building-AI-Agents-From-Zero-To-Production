## 1. Executive summary

This course is **not a legacy course**. It already uses the Microsoft Agent Framework,
Hosted Agents, the Microsoft Learn MCP server, `HandoffBuilder` orchestration, DevUI, and
a ChatKit front end. The modernisation required is therefore **targeted**, not a rewrite.

Three themes drive every recommendation below:

| # | Theme | Verified? | Impact |
|---|-------|-----------|--------|
| A | **Brand rename**: *Azure AI Foundry* → *Microsoft Foundry* (official, effective Jan 2026) | ✅ Microsoft Learn / Product Terms | Terminology across all lessons |
| B | **Agent Framework API drift**: the SDK surface the samples import no longer resolves against the currently published packages | ✅ Package introspection (see §4) | Code will not import/run as written |
| C | **Content gaps**: empty Lesson 3 README, a designed-but-missing agent, no dedicated Toolbox/MCP/Memory/Observability/A2A modules | ✅ Repo inspection | Learner journey breaks |

**Highest-priority action:** migrate the code samples from the retired
`agent_framework.azure` client classes to the current **`agent_framework.foundry`**
surface (`FoundryChatClient`, `FoundryAgent`, …). Everything else (terminology, links,
new modules) is lower risk and can proceed in parallel.

## 4. Code validation — the critical finding (Agent Framework API drift)

Introspection of the **currently published** packages (`agent-framework 1.2.0`,
`agent-framework-foundry 1.2.0`, `agent-framework-core 1.2.0`, plus the `-devui`,
`-chatkit`, `-a2a`, and `azure-ai-agentserver-*` companions) shows the SDK surface has
moved to a **Microsoft Foundry-branded namespace**. The imports the samples use no
longer resolve.

### 4.1 Import migration map (verified)

| Repo uses today | Resolves against current packages? | Current equivalent |
|-----------------|-----------------------------------|--------------------|
| `from agent_framework.azure import AzureAIClient` | ❌ No | `from agent_framework.foundry import FoundryChatClient` |
| `from agent_framework.azure import AzureAIAgentClient` | ❌ No | `FoundryChatClient` (with a project endpoint) |
| `from agent_framework.azure import AzureOpenAIChatClient` | ❌ No | `FoundryChatClient` / `agent_framework.openai` client |
| `from agent_framework import ChatAgent` | ⚠️ Moved | `Agent` / `FoundryAgent` (`agent_framework.foundry`) |

| `from agent_framework import HostedVectorStoreContent` | ❌ No | Vector-store wiring via the Foundry file-search tool |

### 4.3 Reproducibility problem

`requirements.txt` pins `agent-framework --pre` (unpinned prerelease). This is
**non-reproducible**: a fresh `pip install` today pulls a package set whose API differs
from the one the samples were written against, so the course breaks for new learners with
no code change on their side. **Pin explicit versions.**

**Confirmed current-SDK facts (agent-framework 1.2.0 / azure-ai-projects 2.1.0):**
- Workflow streaming: `run_stream()` is gone → use `workflow.run(msg, stream=True)` returning a
  `ResponseStream`; events are `WorkflowEvent` with `.data`/`.executor_id`; final result via
  `await stream.get_final_response()`.
- `HandoffBuilder` moved to `agent_framework.orchestrations`; API is `with_start_agent()` +
  `add_handoff(src,[targets])`; participants need `require_per_service_call_history_persistence=True`.

- Two env conventions: `FoundryChatClient` reads `FOUNDRY_PROJECT_ENDPOINT`/`FOUNDRY_MODEL`; the
  `azure-ai-projects` helpers read `AZURE_AI_PROJECT_ENDPOINT`. Samples now fall back across both.

## 5. Structural / consistency defects

1. **Broken README link** — `./lesson-4-agent-deployment/README.md` → should be `./lesson-4-agentdeployment/README.md`.
2. **Empty Lesson 3 README** — critical content gap.
3. **Missing "Task Recommendation Agent"** — Lesson 1 designs a GitHub-MCP agent; `.env.example` ships `GITHUB_PERSONAL_ACCESS_TOKEN` for it; no code implements it. Either build it or realign the Lesson 1 design to what ships.
4. **Env-var drift** in Lesson 4: `deploy.py` sets `AZURE_AI_PROJECT_ENDPOINT` + `MODEL_DEPLOYMENT`; `agent.yaml` expects `AZURE_OPENAI_ENDPOINT` + `AZURE_OPENAI_CHAT_DEPLOYMENT_NAME`; `main.py` uses `AzureOpenAIChatClient`. Pick one contract.
5. **Endpoint-format drift**: root `.env.example` uses `https://<proj>.services.ai.azure.com`; Lesson 4 `.env.example` uses `https://<proj>.<region>.api.azureml.ms`. The current Foundry project endpoint format is `https://<resource>.services.ai.azure.com/api/projects/<project>`.
6. **Model drift (RESOLVED)**: samples previously mixed `gpt-4o` (deploy/agent.yaml), `gpt-5-codex` (agents), and "GPT-4.1 or later" (Lesson 2). Per the [Microsoft Foundry model retirement schedule](https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/model-retirement-schedule), **GPT-4o and GPT-4.1 are deprecated (2026 retirement); official replacement is `gpt-5.1`**. All general/chat/eval deployments now standardise on `gpt-5.1` (version `2025-11-13`); coding samples keep `gpt-5-codex` (GA to 2027-03-17). No deprecated models remain in samples.
7. **Deprecated async pattern** in `learning-recommendation-agent.py`.
8. **`.DS_Store` files (RESOLVED)** — 4 committed macOS metadata files removed from tracking; `.gitignore` now ignores `.DS_Store` / `**/.DS_Store`.

## 6. Learner-experience review

**Beginner friction**
- No single "Prerequisites & setup" page: `az login`, model deployment, `pip install`,
  and vector-store creation are scattered. New devs will miss a step.
- Lesson 2 setup ends abruptly after `.env` copy — no "run your first agent" checkpoint.
- Empty Lesson 3 leaves a beginner with no guidance between "develop" and "deploy".

**Intermediate friction**
- Trade-offs (local DevUI vs hosted agent; when to use handoff vs a single tool-rich
  agent) are not discussed.
- Observability/evaluation is code-only (Lesson 3 has no prose explaining *why* or *how to
  read results*).

**Advanced friction**
- No enterprise concerns: cost of hosted agents, scaling replicas, security (managed
  identity, private networking), governance of tools (Toolbox), MCP approval workflows.
- No Memory or A2A coverage despite both being first-class in the current SDK.

**Prerequisite-gap report:** add an explicit, single prerequisites checklist (Azure sub,
Foundry project, model deployment, Python 3.12+/3.13, Node 18+, Docker, `azd`).

## 7. Architecture-modernisation notes

Current Lesson 4 diagram is good but predates the current platform vocabulary. Updated
diagrams should show: **Foundry Agent Service** hosting the workflow; **Toolbox** as the
governed tool registry; **Hosted MCP** tools; **Foundry Memory** for persistence;
**Observability/Evaluation** pipeline (traces → evaluators → report); and optional **A2A**
edges between specialised agents. A Mermaid version is included in the new modules so the
diagram renders in-repo and stays diff-able.
