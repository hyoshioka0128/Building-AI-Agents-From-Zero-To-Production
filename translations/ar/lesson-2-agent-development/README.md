# الدرس 2 تطوير الوكيل

مرحبًا بكم في الدرس الثاني من "دورة بناء وكيل ذكاء اصطناعي من الصفر إلى الإنتاج"!

في هذا الدرس سنغطي:

- الأدوات لإنشاء وكلاء الذكاء الاصطناعي لدينا
  
- تعليمات إعداد موارد التطوير لدينا

- أفضل ممارسات تطوير وكلاء الذكاء الاصطناعي
  
- استعراض شفرة لإنشاء وكلاء الذكاء الاصطناعي لدينا
  
لنبدأ بالنظر إلى الأدوات التي سنستخدمها لإنشاء وكلاء الذكاء الاصطناعي لدينا.

## الأدوات وتعليمات الإعداد

### Microsoft Foundry

للوصول إلى نماذج اللغة الكبيرة (LLMs) سنستخدم [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry). هناك تكاليف مرتبطة باستخدام Foundry لذا يرجى التأكد من اتباع تعليمات إعداد الحساب إذا لم يكن لديك وصول بالفعل.

### نماذج OpenAI

عينات شفرة الوكيل في هذه الدورة معدة لاستخدام نماذج OpenAI من خلال [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry).

استخدم هذا الدليل لتعلم كيفية نشر نموذج باستخدام Foundry: [نشر نماذج Microsoft Foundry في بوابة Foundry](https://learn.microsoft.com/azure/ai-foundry/foundry-models/how-to/deploy-foundry-models?view=foundry-classic)

اختر نموذجًا من سلسلة GPT-5 (على سبيل المثال `gpt-5.1`) لهذه الدورة. تجنب النماذج المتوقفة مثل GPT-4o و GPT-4.1، التي تصل نهاية عمرها في 2026.

### إطار عمل Microsoft Agent

كما ذُكر سابقًا، سنستخدم [Microsoft Agent Framework](https://github.com/microsoft/agent-framework) لإنشاء وترتيب وكلاء الذكاء الاصطناعي لدينا.

ستحتاج إلى **بايثون 3.12 أو أحدث**. لتثبيت Microsoft Agent Framework والحزم المطلوبة الأخرى، شغّل الأمر التالي أثناء وجودك في الدليل الجذري لهذا المشروع:

```bash
pip install -r requirements.txt
```

### المصادقة مع Azure

الوكلاء يقومون بالمصادقة على Microsoft Foundry باستخدام بيانات اعتماد Azure CLI الخاصة بك
(`AzureCliCredential`)، لذلك يجب عليك تسجيل الدخول قبل تشغيل أي عينة:

```bash
az login
# إذا كان لديك أكثر من اشتراك، اختر الاشتراك الخاص بمشروع Foundry الخاص بك:
az account set --subscription "<your-subscription-id>"
```

تأكد من أن حسابك يمتلك دور **Azure AI User** (أو ما يعادله) في مشروع Foundry
حتى يتمكن من استدعاء API للنموذج والوكلاء.

### إعداد متغيرات .env

لتشغيل عينات الشفرة في هذه الدورة، ستحتاج إلى إنشاء ملف `.env` في الدليل الجذري لهذا المشروع.

لجعل الأمر أسهل، يمكنك نسخ ملف `.env.example` المزود:

```bash
cp .env.example .env
``` 

ثم املأ المتغيرين اللذين يقرأهما الوكلاء (يقوم `FoundryChatClient` بالتقاطها
تلقائيًا):

| المتغير | ما هو | أين تجده |
|----------|------------|------------------|
| `FOUNDRY_PROJECT_ENDPOINT` | نقطة نهاية **مشروع** Foundry الخاص بك، وتنتهي بـ `/api/projects/<project>` | بوابة Foundry → مشروعك → **نظرة عامة** → *نقاط النهاية* |
| `FOUNDRY_MODEL` | اسم نشر النموذج الذي تعمل عليه وكلائك (مثلاً `gpt-5.1`) | بوابة Foundry → **النماذج + نقاط النهاية** |

### إنشاء مخزن المتجهات للموظفين

أحد العينات — **وكيل بحث الموظفين** — يبحث في دليل الموظفين الموجود في
مخزن **المتجهات** في Microsoft Foundry. أنشئه مرة واحدة وانسخ المعرف الذي يطبعه في ملف `.env`
كـ `VECTOR_STORE_ID` (شغّل من جذر المستودع حتى يلتقط ملف `.env` الخاص بك):

```bash
python lesson-2-agent-development/setup_vector_store.py
```

### تشغيل عينة

لكل وكيل واجهة تطوير محلية خاصة به DevUI. على سبيل المثال:

```bash
python lesson-2-agent-development/employee-search-agent.py
```

ثم افتح الرابط المطبوع `http://localhost:<port>` في متصفحك للدردشة مع الوكيل.

## الوكلاء في هذا الدرس

كل عينة هي وكيل مستقل مبني باستخدام Microsoft Agent Framework. معًا
ينفذون السيناريوهات التي صممتها في [الدرس 1](../lesson-1-agent-design/README.md):

| العينة | سيناريو الدرس 1 | الأداة المستخدمة | المنفذ |
|--------|-------------------|-----------|------|
| `employee-search-agent.py` | السيناريو 1 — بحث الموظفين | بحث ملفات مستضاف من Foundry عبر مخزن متجهات | 8090 |
| `task-recommendation-agent.py` | السيناريو 2 — توصية المهام | خادم **GitHub MCP** (أداة MCP مستضافة) | 8095 |
| `azure-learning-agent.py` | السيناريو 3 — مساعد الشفرة (بحث) | خادم **Microsoft Learn MCP** (أداة MCP مستضافة) | 8092 |
| `coding-agent.py` | السيناريو 3 — مساعد الشفرة (برمجة) | **مفسر الشفرة** | 8093 |
| `learning-recommendation-agent.py` | وكيل داعم | Learn MCP + الاستنتاج | 8091 |
| `agent-orchestration.py` | يربط السيناريوهات معًا | تنظيم **نقل المهمة** لوكلاء متعددين | 8094 |

> **ملاحظة حول وكيل توصية المهام.** `task-recommendation-agent.py` يحتاج إلى
> `GITHUB_PERSONAL_ACCESS_TOKEN` في ملف `.env` الخاص بك (أنشئ واحدًا في
> <https://github.com/settings/personal-access-tokens/new>). يقرأ نشاط GitHub الأخير للمطور
> ويوصي بـ 1-3 قضايا مفتوحة تتطابق — وهو بالضبط تصميم السيناريو 2.
> هذه العينة الوحيدة التي تستدعي GitHub؛ الأخرى تحتاج فقط إلى مشروع Foundry الخاص بك.
