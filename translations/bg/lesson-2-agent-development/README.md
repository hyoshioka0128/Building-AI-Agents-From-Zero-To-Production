# Урок 2 Разработка на агенти

Добре дошли във втория урок от курса "Създаване на AI агент от нулата до продукция"!

В този урок ще разгледаме:

- Инструментите за създаване на нашите AI агенти
  
- Инструкции за настройка на нашите ресурси за разработка

- Най-добри практики за разработка на AI агенти
  
- Преглед на кода за създаване на нашите AI агенти
  
Нека започнем с разглеждането на инструментите, които ще използваме за създаване на нашите AI агенти.

## Инструменти и инструкции за настройка

### Microsoft Foundry

За достъп до Големи езикови модели (LLMs) ще използваме [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry). Има разходи, свързани с използването на Foundry, затова уверете се, че следвате инструкциите за настройка на акаунт, ако вече нямате достъп.

### OpenAI модели

Примерните кодове на агентите в този курс са настроени да използват OpenAI модели чрез [Microsoft Foundry](https://azure.microsoft.com/products/ai-foundry).

Използвайте това ръководство, за да се научите как да разположите модел с Foundry: [Deploy Microsoft Foundry Models in the Foundry portal](https://learn.microsoft.com/azure/ai-foundry/foundry-models/how-to/deploy-foundry-models?view=foundry-classic)

Изберете един модел от серията GPT-5 (например `gpt-5.1`) за този курс. Избягвайте вече несъществуващите модели като GPT-4o и GPT-4.1, които ще бъдат прекратени през 2026 г.

### Microsoft Agent Framework

Както беше споменато по-рано, ще използваме [Microsoft Agent Framework](https://github.com/microsoft/agent-framework), за да създаваме и оркестрираме нашите AI агенти.

Необходим ви е **Python 3.12 или по-нова версия**. За да инсталирате Microsoft Agent Framework и другите необходими пакети, изпълнете следната команда в главната директория на този проект:

```bash
pip install -r requirements.txt
```

### Аутентикация в Azure

Агентите се аутентикират в Microsoft Foundry с вашите Azure CLI идентификационни данни
(`AzureCliCredential`), затова е необходимо да влезете в системата преди да стартирате някой примерен код:

```bash
az login
# Ако имате повече от един абонамент, изберете този с вашия Foundry проект:
az account set --subscription "<your-subscription-id>"
```

Уверете се, че вашият акаунт има ролята **Azure AI User** (или еквивалентна) в проекта Foundry,
за да може да използва API-тата за модели и агенти.

### Настройка на променливи в .env

За да стартирате примерните кодове от курса, трябва да създадете файл `.env` в главната директория на този проект.

За да улесните това, можете да копирате предоставения `.env.example` файл:

```bash
cp .env.example .env
``` 

След това попълнете двете променливи, които агентите използват (клиентът `FoundryChatClient` ги зарежда
автоматично):

| Променлива | Какво представлява | Къде да я намерите |
|----------|------------|------------------|
| `FOUNDRY_PROJECT_ENDPOINT` | Крайна точка на вашия Foundry **проект**, завършваща с `/api/projects/<project>` | Foundry портал → вашият проект → **Обзор** → *Крайни точки* |
| `FOUNDRY_MODEL` | Име на разположения модел, на който работят вашите агенти (например `gpt-5.1`) | Foundry портал → **Модели + крайни точки** |

### Създаване на векторно хранилище за служителите

Един пример — **Employee Search Agent** — търси в указател на служители, съхранен във
Microsoft Foundry **векторно хранилище**. Създайте го веднъж и копирайте изписания идентификатор в `.env`
като `VECTOR_STORE_ID` (стартирайте от главната директория на репозитория за да зареди вашия `.env`):

```bash
python lesson-2-agent-development/setup_vector_store.py
```

### Стартиране на пример

Всеки агент стартира собствен локален DevUI. Например:

```bash
python lesson-2-agent-development/employee-search-agent.py
```

След това отворете отпечатания URL `http://localhost:<port>` в браузъра си, за да си чатите с агента.

## Агентите в този урок

Всеки пример е самостоятелен агент, създаден с Microsoft Agent Framework. Заедно те
реализират сценариите, които проектирахте в [Урок 1](../lesson-1-agent-design/README.md):

| Пример | Сценарий от урок 1 | Използван инструмент | Порт |
|--------|-------------------|-----------|------|
| `employee-search-agent.py` | Сценарий 1 — Търсене на служител | Файлово търсене във векторното хранилище, хоствано в Foundry | 8090 |
| `task-recommendation-agent.py` | Сценарий 2 — Препоръка за задача | **GitHub MCP** сървър (хостван MCP инструмент) | 8095 |
| `azure-learning-agent.py` | Сценарий 3 — Асистент по код (изследване) | **Microsoft Learn MCP** сървър (хостван MCP инструмент) | 8092 |
| `coding-agent.py` | Сценарий 3 — Асистент по код (код) | **Code Interpreter** | 8093 |
| `learning-recommendation-agent.py` | Поддържащ агент | Learn MCP + логика | 8091 |
| `agent-orchestration.py` | Свързва сценариите | Оркестрация на многоагентова **передача** | 8094 |

> **Забележка за агента за препоръка на задачи.** `task-recommendation-agent.py` изисква
> `GITHUB_PERSONAL_ACCESS_TOKEN` във вашия `.env` (създайте такъв на
> <https://github.com/settings/personal-access-tokens/new>). Той чете последната активност на разработчик в GitHub
> и препоръчва 1–3 отворени задачи, които съответстват — точно както е зададено в Сценарий 2.
> Това е единственият пример, който се свързва с GitHub; останалите изискват само вашия Foundry проект.
